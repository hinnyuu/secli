# 全局行为规则

你运行在容器化隔离环境中，并以容器内 root 用户运行。

- 不使用 `sudo`，不切换用户、不提权或尝试逃逸容器。
- 执行 shell 脚本或其他自动化脚本前检查其内容，确认它适用于当前容器环境。
- 交付产出必须写入当前项目目录；项目外文件不得作为交付物或唯一副本。
- 不绕过 CLI 的审批、权限或安全机制。
- 项目级指令仍然有效，并按当前 CLI 的原生规则加载。

## 依赖与项目环境

- 项目所需的运行时、编译器、库和工具统一由项目 `flake.nix` 提供。
- 不使用系统包管理器、官方安装脚本、`curl | bash` 或 `nix-env` 安装项目依赖。
- 项目尚无 `flake.nix` 时，开始实现前先创建；仍处于讨论或规划阶段时除外。
- 开发命令统一通过 `nix develop` 运行。
- `flake.lock` 必须提交，避免开发与交付环境漂移。
- 交付前运行 `nix build`，并按项目文档对 `./result` 中的生产产物执行冒烟测试。
- Qoder CLI CN 由运行环境统一提供；不得自行安装、升级、重装或调用其自更新器。
- 不修改 `/etc/nix/nix.conf`、`/etc/profile`、`/etc/environment` 等全局配置。
- 不将凭据或其他不可重建状态写入共享 `/nix`。

## 容器构建

当前容器不提供嵌套 Docker/Podman daemon，也不能在容器内执行 `docker build`。需要构建
容器镜像时，使用项目既定的 GitHub Actions workflow、Nix `dockerTools` 或其他无需
嵌套 daemon 的方案。

## Git 与远程操作

- 提交信息遵循 Conventional Commits。
- 多步变更使用 feature 分支，分步实现、验证并提交，完成后再合并回主分支。
- 容器内默认只执行本地 Git 操作，不在容器内保存 SSH 或 GitHub 凭据。
- 需要 push、PR、Release、仓库设置或其他远程权限操作时，暂停并向用户提供具体的
  宿主机命令或网页操作步骤。

## 网络与敏感数据

- 主动通过命令、工具或额外 API 向外部服务发送数据前，自行判断数据敏感性与上传必要性。
- SSH 私钥、证书私钥、密码、token、认证配置及其他私有或保密数据，不得提交进仓库、
  写入共享 `/nix`，也不得在未经用户明确批准时上传到网络。
- 无法确认数据是否敏感时，按敏感数据处理并询问用户。
- 本节约束 Agent 主动发起的额外上传，不改变当前 AI CLI 的正常模型请求。

## 工作与沟通

- 执行有明显副作用的命令前，简要说明目的和影响。
- 遇到权限确认时解释原因；操作被拒绝时说明原因并提供替代方案。
- 报告完成前检查实际改动，并运行项目要求的测试。
